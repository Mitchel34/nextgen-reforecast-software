# State and recovery contract

This is a read-only inspection of resident preserved source and historical receipts. No hydrologic model, build, project diagnostic script or test was executed. `SOURCE_VERSION_MAP.json` defines REVIEW, D, N, L and C and gives full file hashes. Public aliases intentionally omit local account paths and cloud account identifiers. Referenced evidence remains in the private preservation snapshot, so these references alone are not a public executable distribution.

## Issue boundary and inherited state

For origin H and issue I, the parent has completed hourly intervals [H,I), including [I−1h,I), and its land components and routing clock are at I. The provider label is the interval START. N/include/shared_history/Runtime.hpp:484–492 checks the framework start and each BMI component's completed epoch; :515–534 advances routing to the same boundary before branching. The parent does not consume forecast weather or an interval starting I before the fork. A branch consumes interval starts I through I+17h and produces targets I+1h through I+18h. At termination exactly 18 branch steps and the declared parent history count are required (:525–549).

`fork()` copies the whole live native process address space, including CFE storage, Noah/Fortran arrays and module state, SLOTH, clocks, coupler objects and stable provider graph. This is stronger than copying selected BMI variables but is same-host live process inheritance, not a serializer or a portable checkpoint. The source does not enumerate and independently attest every hidden state variable in each physical library. `N/include/shared_history/SwitchingProvider.hpp:39–60` installs a stable wrapper before nested BMI associations and permits exactly one switch, in the child, to issue-specific forcing. Same-weather control is an explicit alternative qualification mode. The actual production wrapper uses issue-specific CSVs. CSV validation requires eight distinct quantities, finite values and exactly 18 interval-start rows (:17–36).

## Isolation and resource restrictions

N/include/shared_history/Runtime.hpp:407–460 waits for a pool slot, requires one live thread, flushes streams, prepares branch inputs and snapshots the parent router at I. In the child, inherited routing handles are abandoned without stopping the parent's router, runtime streams are closed, and inherited child PID ownership is cleared. Recognized dormant legacy writers are redirected to private `/dev/null` descriptions; unknown writable/component-diagnostic handles refuse the fork (:376–391, :431–442). Disabling Noah diagnostics is part of the qualified configuration, not a substitute for an ownership audit of another component.

Each regular read-only input is reopened into a new open-file description, checking device/inode/size and restoring its offset before rebinding the same descriptor number (N/include/shared_history/ChildOwnership.hpp:11–29). A plain duplicate descriptor would share file offsets. The child starts its own routing process, restores the channel snapshot and acknowledges isolation; only then may the parent advance. Parent cursor positions and router epoch are checked (:446–458). Child shutdown owns only its own router and children (:552–561); Linux parent-death signaling is set (:425–427). Process memory isolation does not make arbitrary external component I/O safe.

The actual production controller requires Linux ARM64, uses a separate routing process, and sets OMP, OpenBLAS, MKL and NumExpr thread counts to 1 (C/src/nextgen_reforecast/production_day_controller_v1.py:245,294–297). The native fork inspects Linux `/proc/self/task` and `/proc/self/fd` (N/include/shared_history/Runtime.hpp:282–290). MPI, embedded Python and built-in NGen routing are disabled in the source lock; external routing supplies channel continuation. macOS, Windows, x86_64 binaries, multithreaded land execution, MPI, multiprocessing spawn and distributed cross-host branching are not established by these receipts.

V2 enforces declared history/issue bounds ≤100,000, walltime ≤604800 s, child pool ≤32, and parent + children × per-child CPU reservation ≤host (N/include/shared_history/Runtime.hpp:138–159). These are reservations, not per-child cgroups. The history-value count is not total RSS. Production provides hard-coded domain/layout admission around this kernel; arbitrary domain reuse requires extraction work.

## Channel checkpoint and durable artifacts

C/src/nextgen_reforecast/shared_history_routing_service_v1.py:250–298 snapshots ordered segment `qu0`, `qd0`, `h0` as float32 q0, binding hash, common origin, epoch, shape and checksums. Restore only enters a fresh session at the common origin, validates identity and layout, sets q0/time and rebuilds topology caches. Velocity is an output, not a q0 input. This serializer is qualified for the restricted channel profile: HYFeaturesNetwork, V02-structured, twelve 300-second steps per hour. Enabled waterbody, assimilation, GIUH, hybrid/refactored/coastal and external restart settings are rejected (:60–89). A q0 file is not a land-state checkpoint.

Per-issue persistence is `FORECAST_ROWS.csv`, `COMMIT.json` and `SHA256SUMS`. `seal_branch_commit` requires an 18-step native receipt, exactly one zero-exit reaped-child journal row, exact gauge/lead coverage and finite nonnegative flows. It binds the numerical binary, origin, weather manifests, hydrofabric, component configuration and routing source. It writes and fsyncs a temporary directory, renames it atomically and fsyncs its parent (C/src/nextgen_reforecast/shared_history_recovery_v2.py:49–161). Existing commits are verified and never silently overwritten; `verify_commit`:164–195 checks exact artifact membership, binding, checksums, keys and coverage. Receipt hashes establish lineage, not retained numeric land state or cryptographic authentication against a malicious writer.

Day custody is an output transaction boundary. The native parent drains children and flushes, then is held during archive custody and cleanup. The controller requires reaped/committed outputs and no pending cleanup before ACK (production_day_controller_v1.py:73–107). The cleanup hook is deferred until the reaped journal appears, avoiding a parent/reaper deadlock. An uncertain upload is reconciled against the exact immutable object; this transport handling is distinct from scientific model retries. `shared_history_day_shard_v1.py:178–241` archives commits and explicitly records `state_checkpoint:false`. Its publication marker prevents use of unpublished partial archives. `DayCustodyBoundary` stores no hydrologic state.

## Failure and reconstruction

* **Child fails after the parent advances:** native completion requires zero exit; failure/timeout stops owned work without automatic retry or cold fallback (N/include/shared_history/Runtime.hpp:331–359,552–561). The parent cannot fork again from the already-passed issue using the current state. A new admitted run must reconstruct the earlier issue by identical historical replay. Any unfinished branch files remain uncommitted.
* **Parent or host is lost:** there is no complete durable land-state restore. Replay starts from the recorded original configuration and origin and advances the same historical forcing. This aims to reconstruct the same scientific initialization; changing the origin, forcing, parameters or physical binaries would be a different run. Exact multi-year crash/replay equivalence is not newly established here.
* **Outputs exist without a valid commit:** they cannot be counted as completed issues or used to suppress forks. The commit routine requires a reaped-child journal and complete bound outputs. Invalid/mismatched commits fail verification rather than being repaired by assumption.
* **Completed issues:** verified commits can be reused; `recovery_plan`:198–231 returns only uncommitted issue epochs while preserving uninterrupted historical replay from H. Skipping a forecast does not skip historical state advancement. The plan is side-effect-free and does not itself launch a recovery worker. It checks positive remaining authority, finite measured history throughput and a declared replay reserve; the throughput number is not independently measured by the planner. Production-scale automatic recovery orchestration is not demonstrated by the mere presence of this helper.
* **Assets missing:** replay needs exact native/middleware/component runtime, domain/parameters/configuration, dense historical input bytes from original H through replay stop, source bindings and remaining issue-specific forcing. A manifest key or retained discharge CSV cannot recreate missing weather bytes. The production reader rejects absent, unsafe, oversized or dataless bound inputs (`production_execution_recipe_v1.py:43–50`; `production_forecast_shards_v1.py:29–44`). It does not authorize substituting weather, shorten spinup or switch to cold initialization. Missing inputs are a restoration dependency.
