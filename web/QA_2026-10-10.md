# Internal browser prototype QA — 10 October 2026

This records developer inspection of the local request prototype. It is **not a participant study**, an independent reproduction, a source-coverage verification or model-run evidence. `UX_E1` is the intended level for a future protocol-bound prototype evaluation. No participant IDs, usability rates, completion times, generated streamflow or verified datasets are assigned.

## Automated contract evidence

`node --test web/tests/request.test.mjs` passed all 12 tests using Node v24.16.0 on macOS. Tests cover inclusive UTC issue days/exclusive stop, exact issue/target/row counts, leap/calendar and year boundaries, daylight-saving independence, reversed/oversized periods, minimum representable initialization headroom, lead constraints, retained-versus-generated rows, unresolved identifiers, unsupported continuous-mode translation and JSON round-trip.

The campaign agent independently reviewed the request/time contract. Review found and fixed two boundary errors: a nominal maximum issue count could exceed the engine's history bound once initialization/forecast headroom was added, and year 1's first issue day left no representable earlier origin. Both now have regression assertions. The review also checked that input edits invalidate the downloadable review and that user-supplied text is rendered as text. Five cross-language tests in `tests/translation.test.mjs` compare browser arithmetic with engine normalization using synthetic test-only initialization values, which do not select a scientific origin. The combined command `node --test web/tests/*.test.mjs` passed all 17 tests (12 request tests plus 5 browser-to-Python tests).

## Limitations and next integration

These checks establish the exercised local interactions and deterministic request arithmetic. They do not establish full keyboard/screen-reader accessibility conformance, cross-browser compatibility, user comprehension, durable storage, authentication, live basin resolution, coverage, preparation, model correctness, runtime estimates or hosted availability. Browser focus/labels and responsive layout have a useful initial implementation, but a separate accessibility pass and the protocol-bound formative study remain needed.

The default example differs from the original two-issue scientific benchmark and supplies no initialization policy. Future/historical dates are merely recorded requests until coverage is checked. Submitted request JSON cannot be passed directly to the engine as a prepared campaign.

Source identities and machine-readable scope are in [QA_2026-10-10.json](QA_2026-10-10.json). The coordinator owns integrated repository tests, CI and final publication evidence. A running local preview can end with its development process; it is not a deployment.
