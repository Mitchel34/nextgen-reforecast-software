## Routing confluences and the gauge surrogate

The [pinned t-route reader](https://github.com/NOAA-OWP/t-route/blob/533fbd98362efdafae62392308727de4f0d4cc20/src/troute-network/troute/HYFeaturesNetwork.py) constructs a nexus-to-upstream-reach dictionary from downstream nexus IDs and reach keys. In this domain, five confluence nexuses have 3, 8, 3, 6 and 4 upstream reaches. Multiple dictionary entries with the same nexus key collapse to one reach. Supplying aggregated `nex-*` runoff would assign the merged lateral inflow to that reach and leave the other tributaries without their own lateral inflow. This is an admission error because travel through the tributary channels would change.

The new routing configuration uses the reader's `cat-*` mode and explicitly names `Q_OUT`. The reader converts each catchment's timestep depth using its `areasqkm` value, then preserves the numeric catchment ID as the routing reach ID. All 31 public flowpath `divide_id` relationships were verified as unique matches to their corresponding `cat-*` and `wb-*` numbers; all channel parameter keys match this same axis. Channel lengths, roughness, widths and slopes are finite and positive. Only the selected `wb-1017693` points outside the retained domain through `nex-1017694`. The excluded adjacent tributary is not introduced into the reference.

Output selection uses the numeric routed reach `1017693`. The selected full reach remains a spatial surrogate for the interior USGS gauge 03479000. The public fabric's conflicting gauge attribute on another reach must not select the outlet implicitly. There is no claim that this full reach is an exact gauge-location segment or that its discharge equals a junction sum. The [earlier domain review](PUBLIC_WATAUGA_DOMAIN_2026-10-10.md) retains the independent NLDI, gauge-location and drainage-area evidence.

The realization now declares land execution only; t-route is a separately recorded process against the admitted catchment outputs. All 15 CFE output fields are written with 17 significant digits. The candidate CFE configuration bytes remain unchanged. Routing writes NetCDF `Q`, velocity and depth for all 31 reaches every 300 seconds, including the hourly forecast endpoints. This allows independent audits of every routed step and avoids filling in unobserved intermediate values.

## Candidate parameters and scientific release limits

[The pinned CFE documentation](https://github.com/NOAA-OWP/cfe/blob/a349a953ef239ae7470a8365cf614283d7e6ca80/configs/README.md) identifies `soil_params.slop` as a dimensionless gradient multiplier with a documented zero-to-one range. The public `mean.slope_1km` values range from 0.04308 to 0.06209 and satisfy this consumer constraint. [NGIAB's merged parameter fix](https://github.com/CIROH-UA/NGIAB_data_preprocess/pull/74/files) changes its CFE source to that field. These observations support a declared candidate treatment; they do not prove how this distinct archive's values were derived or establish a calibrated drainage parameter.

The Noah candidate retains the pinned NGIAB formula `degrees(arctan(tan(radians(mean.slope))/100))`. The source `mean.slope` values range from 83.1903 to 87.9693. A formula present in a generator is evidence of implementation, not proof of the input field's scientific units. The bound public GeoPackage contains no `gpkg_metadata` or `gpkg_data_columns` unit declarations. The attempted primary `NOAA-OWP/hydrofabric` repository lookup returned HTTP 404; no mirrored data dictionary was used to resolve source units. These source-unit and derivation gaps remain explicit release requirements. The adapter performs no speculative conversion and preserves the candidate CFE values exactly.

The declared cold initial conditions and approximately 31 days of history do not prove state convergence. Point radiation sampling requires profile-level physical review before release. Current archive versions and later-uploaded NWM generations do not demonstrate historical causal availability. Hydrofabric redistribution terms and the project-wide license also remain unresolved. These limitations constrain reference interpretation; they do not prevent an explicitly labeled deterministic diagnostic execution once its runtime and recipe are separately admitted.

Nine targeted synthetic tests pass for confluence/catchment mapping, the outlet cut, missing or invalid channel parameters, source archive corruption, inclusive endpoint assignment, named routing input/output selectors, corrupted assets/reports, new-revision custody, source-axis changes and destination overwrite refusal. They initialize no models. A failed initial input-adaptation attempt exposed `wb-` prefixes in routing attribute keys; it stopped before creating an output directory and was repaired by accepting only the source-supported key forms and verifying the exact numeric axis. Physical acceptance remains the next separate evidence step.
