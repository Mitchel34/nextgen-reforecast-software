# Pinned public campaign execution contract

Package 0.1.0a5 adds an operator execution path for one diagnostic profile. It supports Watauga (USGS03479000, full reach1017693), cold origin2021-12-01T00Z, history through2022-01-02T18Z, issues2022-01-01T23Z and2022-01-02T00Z, and all18 forecast hours. Retained leads select exported rows only. This does not yet satisfy the researcher goal of entering a gauge and dates in a hosted browser and acquiring everything automatically.

`prepare CAMPAIGN --bundle BUNDLE --output LOCK` checks the resident complete fixture, exact sealed reference bytes, runtime transfer and packaged reference tools. The bundle document uses schema `watauga-v2-execution-bundle/0.1` and exactly three relative `bundle_paths`: `fixture_root`, `reference_root`, `runtime_tar`. Fixture root contains the three admitted case directories. Reference root contains each case's `REFERENCE.json`, `arrays.json`, `lead_reference.json`, plus `set/REFERENCE_SET.json` and `set/lead_reference.json`. No binary or data payload is shipped in the package. The existing `lock` command remains a planning snapshot and cannot admit execution.

The execution lock uses schema `diagnostic-execution-lock/0.1`. It embeds a normalized campaign and derives a separate run/protocol/admission identity from the pinned profile. Campaign resources must declare host2, parent1, branch1, concurrency1 and logical-job wall1800; actual containers have the pinned2CPU hard quota and numerical libraries use one thread. Paths may move together without changing their relative bindings. The source references and inputs are never rewritten.

`run LOCK --asset-root ROOT --execution-root NEW --archive NEW --docker-host unix:///EXPLICIT/SOCKET [--docker-config DIR]` verifies assets before launch, claims the lock once in `ROOT/.execution-claims/`, refuses existing namespaces, reserves each model process before launch, and captures stages before stopping/removing their containers. It does not start Docker, create a VM, pull/build an image, use a global context or make network requests. Each job uses the immutable admitted image and exact exported native executable. The parent validates fatal logs, complete native clocks/fields and exact diagnostic warning inventory before routing. Full routed output is normalized and all input bytes are checked again.

A successful `CAPTURE.json` means new stages were captured; it is not completed scientific evidence by itself. `commit_result` invokes the frozen seal/audit tools, compares complete canonical arrays to the independent sealed reference arrays, checks the full issue/lead key set, then produces the selected export. Only the protocol envelope identity may differ in array comparison; all axes, clocks, units, metadata and values must match exactly.

A completed result lives under `commits/<result_identity_sha256>/` with a manifest and full captured payload. Files and directory entries are flushed before atomic publication; `CURRENT.json` is published last, once. No incomplete attempt or staging directory is completed. `status ARCHIVE [--lock LOCK]` verifies before reporting completed; `verify` rehashes every bound byte; `export --output NEW` publishes a new verified directory atomically. Corrupt, missing, linked, dataless or mismatched results fail closed. Repeated completion reuse requires fresh verification and exact lock identity. Neither live claims nor ledgers are reset. `resume` remains unavailable: no restart or recovery is claimed.

These diagnostics retain the v2 unit fallback warnings and declared scientific limits. Execution receipts and exact reference agreement establish reproducible serialized output under this pinned operator environment; they do not establish model skill, correct physical parameterization, a clean public builder or usability for outside researchers. See the increment and manuscript evidence plan for acceptance and remaining release gates.
