The separately authorized [public Watauga fixture](../docs/PUBLIC_WATAUGA_FIXTURE_PLAN.md) prepares new source-bound inputs without replacing E03 or inheriting its results. Any physical reference for those inputs requires a separate prospective protocol and allowance. For issue \(I\), the historical parent has consumed \([H,I)\); forecast provider labels are \(I\) through \(I+17\mathrm{h}\), and the generated target times are \(I+1\mathrm{h}\) through \(I+18\mathrm{h}\). Request normalization can map an explicit UTC cadence or an issue list to the same canonical schedule. Equivalence of schedules is a planner statement; it does not establish that the source archive contains every requested issue. Similarly, output selection changes a campaign/product identity while the underlying antecedent physical-state inputs may remain the same. The planner's domain input identity and the planning lock's per-domain provenance identity serve different scopes: the latter binds the wider campaign context, including issue schedule, retained selection, resources and declared metadata. It is not a demonstrated key for reusing a physical trajectory. Scientific metadata fields remain null when unknown or explicitly declared-unvalidated when supplied. A lightweight planning lock cannot certify the complete scientific state or make an unavailable model ready to run.

The browser's date labels must state whether they describe issue times or forecast-valid times and show the final target extending beyond the last issue. Prototype choices should be preserved as versioned request behavior and evaluated before they become promises about live source coverage. No-forecast simulation, arbitrary domains or horizons beyond the admitted model profile remain separately scoped decisions.
