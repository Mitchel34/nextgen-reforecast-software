## Target outcome

**Product direction updated 23 September 2026:** [product objectives and journeys](docs/PRODUCT_OBJECTIVES_AND_USER_JOURNEYS.md) now control the researcher-facing experience; the [UX evaluation protocol](docs/UX_EVALUATION_PROTOCOL.md) defines how to assess it. This documentation update does not start implementation or hosting. M0–M7 and RF-001–RF-018 remain stable engine/research milestones; proposed WEB-01–WEB-07 packages add the hosted-product responsibilities.

Deliver a hosted graphical application backed by the versioned `ngen-reforecast` engine. A hydrologist supplies a watershed or USGS/NWM identifier, supported historical dates and forecast lead preferences. The service resolves the domain, acquires and prepares inputs, supplies inspectable scientific defaults, constructs independent forecasts from a continuous historical trajectory, verifies outputs and lineage, and recovers by explicit history replay. Deliver an Environmental Modelling & Software research-article manuscript whose claims are supported by the released code, retained experiments and independent user evaluation.

Initial physical qualification scope: Linux ARM64, pinned NextGen V3 integration, SLOTH/NoahOWP/CFE, channel-only t-route, hourly timesteps and eighteen-hour branches, Watauga plus New River with its two nested outputs. The existing offline interface runs on Linux/macOS; this does not qualify native execution there. The product roadmap adds researcher-selected retained leads within 1–18 and issue schedules independent of the hourly model timestep. Explicit irregular issue lists already work in the planner; cadence expansion and retained-lead selection are planned. Complete portable land checkpoints, arbitrary BMI realizations, reservoir/assimilation routing and ML correction remain outside the initial physical scope. A hosted browser workflow and automatic preparation are requirements for the first usable owner-facing product; local engine increments precede that release. Continuous historical simulation and curated study recipes are separately identified proposals, not supported runtime modes today.

The primary user is a hydrologist or environmental researcher using a browser without a Python, notebook, CLI or local-installation prerequisite. The package/CLI remains an engine and operator interface. The intended product is a saved experiment, reproducible execution and a research-ready archive with a Methods report. Domain preparation, meteorological regridding, general NextGen deployment and downstream evaluation should use compatible ecosystem tools through documented adapters. HYDRA is an optional downstream consumer, not a package dependency or the software paper's success criterion.

JSON is the first supported interchange; YAML support can be added behind the same schema later.
2. Provide `init`, `plan`, `ledger`, `report` and runtime `doctor` commands as their implementations become available. Unimplemented `run`, `resume` and export functionality must be clearly unavailable. A plan is not permission, launch readiness or evidence of a model run.

## Contracts that must survive extraction

- Parent historical state at issue I has consumed intervals [origin,I); branch provider labels start at I, and outputs target I+1h through I+18h. A forecast never updates parent history.
- Historical precipitation and forecast rain-rate semantics are distinct. No double conversion, shifted label, implicit imputation or undisclosed source substitution is allowed.
- A domain/state identity includes geometry, realization, parameters, historical forcing/treatments and origin. Nested output gauges do not imply independent domains or authorize sharing different physical configurations.
- A forecast counts as complete only after zero-exit child reaping, key/clock/numeric validation, bound checksums and atomic output publication. A channel snapshot or forecast archive is not a full land checkpoint.
- Recovery preserves original origin and input/runtime identities, verifies existing commits and replays history while suppressing completed issues. Missing/corrupt assets must fail explicitly.
- Historical receipt, new unit test, new synthetic execution, new real-model qualification and independent researcher reproduction are distinct evidence categories.
